# Deploying the demo to Render

This is optional and only exists so the dashboard can be handed to someone as a
link. The pipeline itself is designed to run on a workstation or an on-prem
server, and nothing in it calls out to a network at runtime.

**Before you start, two things worth being deliberate about:**

1. Render is a public cloud host. Everything in this repo is synthetic — the
   models are generated by `src/modelops/synth/` and there is no customer or
   employer data anywhere in it — but you are publishing a URL that anyone with
   the link can open. Decide that is fine before you push.
2. Do not commit `data/`. It is already in `.gitignore`. The hosted instance
   regenerates it on boot.

---

## What was added to make this possible

| File | Why |
|---|---|
| `wsgi.py` | Entry point for a real WSGI server. Seeds the catalog on first boot, because a hosted container starts with an empty disk. |
| `render.yaml` | Render blueprint: Python runtime, build command, start command, health check. |
| `/healthz` route | Returns 200 once the catalog has jobs in it, 503 before that. Render uses it to know when the instance is ready. |
| `gunicorn` in `requirements.txt` | Marked `sys_platform != "win32"`, so it installs on Render and is skipped on your Windows machine. |

## Step 1 — Get the code into a Git repository

Render deploys from GitHub or GitLab. There is no zip upload for web services.

`git` is not currently installed on this machine, so you have two options.

### Option A — Install Git (preferred)

1. Install Git from <https://git-scm.com/download/win>, then restart your
   terminal.
2. From the `model-delivery-poc` folder:

```powershell
git init
git add .
git commit -m "Model delivery pipeline proof of concept"
```

3. Create an empty repository on <https://github.com/new>. Name it something
   presentable like `model-delivery-pipeline`. **Do not** let GitHub add a
   README or .gitignore — you already have them.
4. Push, using the URL GitHub shows you:

```powershell
git remote add origin https://github.com/<your-username>/model-delivery-pipeline.git
git branch -M main
git push -u origin main
```

### Option B — No Git, upload through the browser

If you cannot install software:

1. Create the empty repository on <https://github.com/new> as above.
2. On the new repo page, click **uploading an existing file**.
3. Drag in the contents of `model-delivery-poc` — but **exclude `.venv` and
   `data`**. Both are large and neither is needed. What must go up is:
   `src/`, `config/`, `sql/`, `tests/`, `docs/`, `pyproject.toml`,
   `requirements.txt`, `render.yaml`, `wsgi.py`, `.gitignore`, `README.md`.
4. GitHub's uploader keeps folder structure when you drag folders, but it is
   worth checking afterwards that `src/modelops/web/static/vendor/` made it —
   that is the vendored three.js and the 3D viewer will not load without it.

## Step 2 — Create the service on Render

1. Sign up at <https://render.com> (the free tier is enough) and connect your
   GitHub account.
2. Click **New** → **Blueprint**.
3. Select your repository. Render reads `render.yaml` and pre-fills everything —
   runtime, build command, start command, health check.
4. Click **Apply**.

If the Blueprint option gives you trouble, create it manually instead with
**New** → **Web Service**, and enter:

| Field | Value |
|---|---|
| Language | Python 3 |
| Build command | `pip install --upgrade pip && pip install -r requirements.txt` |
| Start command | `gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 180` |
| Health check path | `/healthz` |
| Instance type | Free |

Add one environment variable: `PYTHON_VERSION` = `3.12.7`.

## Step 3 — Watch the first deploy

The build takes two to four minutes, mostly compiling nothing and downloading
NumPy wheels. Then on first request `wsgi.py` runs the demo pipeline to seed the
catalog, which takes about ten seconds.

In the Render logs you should see, in order:

```
==> Build successful
No catalog found - running the demo pipeline to seed one.
==> Your service is live
```

When it is live you get a URL like
`https://model-delivery-pipeline.onrender.com`. Open it. You should land on the
Operations page with the same numbers you see locally, because the generator is
seeded.

---

## Step 4 — Before you send the link

Check all five tabs load, and in particular that **the Viewer renders 3D
geometry**. That is the one thing most likely to break on a fresh host, and it
breaks for exactly one reason: the vendored three.js files under
`src/modelops/web/static/vendor/` did not get committed. If the viewer shows a
blank canvas, that is the first place to look.

## Things to know before a hiring manager clicks the link

**The free tier sleeps.** After 15 minutes of no traffic Render spins the
instance down. The next request takes 50–60 seconds to wake it, and then another
ten seconds to reseed the catalog. If you send a link and they open it cold,
their first impression is a spinner.

Mitigate it one of two ways:

- Open the link yourself two minutes before the call so it is already warm.
- Or say so in the email. Honestly this works in your favour:

> "Heads up — it is on a free tier that sleeps, so the first page load takes
> about a minute to wake up. It rebuilds its entire dataset from scratch on boot,
> which is why."

**It is a demo host, not the architecture.** If they ask why it is on Render, the
answer is that it is a link, not a deployment. Be ready to say what a real one
would look like: the pipeline running next to the model store rather than across
a network, the catalog on a proper server database instead of SQLite, and
workers scaled horizontally against a shared queue.

**Send the repo too.** The code is more impressive than the dashboard. A hiring
manager for a developer role will read `src/modelops/stages/optimize.py` and
`src/modelops/gltf.py` before they click through seven tabs.

## Local development is unchanged

None of this affects how you run it on your machine:

```powershell
.\.venv\Scripts\python.exe -m modelops demo
.\.venv\Scripts\python.exe -m modelops serve
```

Still bound to `127.0.0.1`, still no network access.
